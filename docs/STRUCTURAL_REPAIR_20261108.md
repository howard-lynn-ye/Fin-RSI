## 仍需真实证据的门槛

1. 明确外部作者来源与研究者暴露；公开外部评测可先推进，私有盲测须另有保管责任与封存。
2. 对不同输出类型先建立任务契约和参考验算；不把同一算法换参数作为独立泛化样本。
3. 固定主要对比、重复采样和必要的 rules-only 控制，并分开报告预算上限与实际成本。
4. 完成真实后端资格检查后，按冻结的模型家族、任务和种子矩阵串行运行，保留全部失败。
5. 按算法/任务家族分析配对差异、异质性与不确定性；观察到什么就报告什么。
6. 依据新证据重写主论文的问题、贡献和结论，再做独立科学复核。负结果也可能有价值，
   但代码修好本身不能保证录用。

## 20 模型接续与上下文合同

接续核对发现旧 P/E 协调器虽生成全 20 模型的固定单元，却只准许 `core` 阶段，并在
冻结计划中只保存当时的核心资格。后续扩展模型不能加入同一计划，重建计划又会使原核心
结果无法按同一计划哈希汇总。新协调器在不更改总体或原资格的前提下，由单次运行 release
绑定后续扩展模型的资格路径及哈希；监督者、worker 和分析器核对同一来源、模型、版本、
后端配置及完整分母，禁止覆盖任何已有资格。

同次修复把 P/E 中断处理接到已验证的 provider 费用解析：半截 JSON、缺少报告和伪完成
标记都保留无效终态与未知费用。最终本地相关套件为 62 项通过、三个仅 Linux 适用的项
跳过；独立窗口另在 WSL 完成三个进程组检查，并复核合成 20 模型在不改计划字节的情况下
接续、汇总及拒绝变造。这不是新模型结果；新 P/E 协调器尚未部署或完成生产 CPU 验收。
