The one valid program is `7b-ma_crossover-11-raw`. Diagnostics (`diagnostics.json`):

- All 24 14B programs, in both arms, apply `cumprod` to split factors that the prompt defines
  as already cumulative; all 24 fail split invariance.
- Of 15 timing failures, 12 move the position at session k when the session-k price changes
  (same-session close) and 3 depend on strictly later data.
- The library's `assert_causal` guard, run post hoc by the worker (k=64), rejected exactly the
  3 strictly-future programs, raised no alarm on the 22 executed programs that passed the
  grader's timing probes, and passed the 12 same-session violations. It tests whether values
  before k depend on data at or after k (feature causality); it is not a one-bar execution-lag
  check. This is a scope finding, not a guard malfunction.
- The remaining 7B failures are runtime errors: output index/shape mismatch, positional
  indexing and Series truthiness errors, `rolling(ddof=...)`, and `.values` on a scalar.

## Interpretation and limits

Supported: open 7B/14B coder first submissions were almost never valid on these four rules,
and the dominant computational errors execute silently. An independent executable oracle, not
execution success, was needed to detect them. Optional documentation produced no library use.

Not supported: any claim that the library or its guards improved generated code, that raw
models "cannot" write financial code in general, or any profitability claim. Four fixed
author-designed rules × three seeds are not twelve independent problems; two sizes from one
model family; training contamination is not ruled out; the fence extraction is post hoc. The
next test is a controller that requires the library call and lag/split/causality checks on
the same frozen tasks, compared with the same parser and runtime.
