By model: 7B valid 1/1/0 of 12 (raw, raw+checks, library+checks); 14B 0/0/0 of 12. All 12

Library arm: 42 of 72 attempts reference `fin_skills`, 8 trace a call, 51 fail to run
(21 output index/columns mismatches, 2 of them raised by the program itself; 9 nonfinite
outputs; 7 argument errors; 5 unsupported pandas arguments; 4 rejected `prices` inputs; 5
others). Seven attempts in three
episodes used the keyword `data_dictionary=` from the interface text in `library_context()`;
the library's `run()` names that argument `data`. All seven also apply `cumprod` to the
cumulative split factors, so they would have failed the split check anyway. The worker's
tracing wrapper uses positional names `name, data`; no attempt failed because of the wrapper
alone (no "missing 1 required positional argument" errors).

## Interpretation
Supported: enforced checks prevent almost all wrong programs from being accepted (accepted
but wrong falls from 91.7% to 8.3%, and to 0% with the library requirement). This is the
library's measured value in this setting: refusing silently wrong results.

Not supported: that enforcement or the library raises the number of correct programs. Valid
deliverables are 1, 1 and 0 of 24; the differences are one program. Enforced library use
mostly fails on interface misuse by these 7B/14B models within three attempts.

Limits: E4 tasks, seeds, models and grader, with checks designed after seeing E4 failures;
not an independent holdout. The interface text's argument name differs from the function.
Three attempts; two sizes of one model family; synthetic rules; no profitability endpoint.
